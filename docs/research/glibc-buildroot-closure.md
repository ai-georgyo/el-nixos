## Findings and how far to trust this (hand-written, 2026-10-18)

**Buildsys package list.** Rocky 10.2's comps (BaseOS 34 groups, AppStream 59,
CRB 1; devel has none) contain **no `buildsys-build` group**, so the list comes
from mock-core-configs (`mock-core-configs/etc/mock/templates/*.tpl`, main
branch):

| mock config | `chroot_setup_cmd` |
|---|---|
| rocky-10 (used here) | `install bash bzip2 coreutils cpio diffutils findutils gawk glibc-minimal-langpack grep gzip info patch redhat-rpm-config rocky-release rpm-build sed tar unzip util-linux which xz` |
| almalinux-10 | same, with `redhat-release` instead of `rocky-release` |
| centos-stream-10 | same, with `centos-stream-release` instead of `rocky-release`, plus `shadow-utils` |

All three use `install_weak_deps=0`, `best=1`. mock rocky-10 enables BaseOS,
AppStream, CRB and extras; `devel` is present but `enabled=0`.

**Validation against real dnf.** `--single-transaction` mode was compared with
`dnf5 --installroot=... --setopt=install_weak_deps=0 install --skip-unavailable
--assumeno <buildsys list> <BuildRequires>` (dnf5 5.4.4 / libsolv from nixpkgs,
against the live Rocky 10.2 BaseOS+AppStream+CRB repos) for 110 SRPMs (10
core ones incl. glibc, gcc, binutils, systemd, kernel, python3.12, plus 100
random): **110/110 identical package sets**. The buildsys transaction alone
(145 packages) is also identical. The table above uses mock's real two
transaction order, which is why it has one package more than a one-shot dnf
install: `rpm-build` needs `/usr/bin/gdb-add-index` in transaction 1, where only
`gdb-minimal` can provide it cheaply; in transaction 2 `gdb` (a glibc BR) brings
`gdb-headless`, which provides it too, but `gdb-minimal` is already installed.
`rpmvercmp` was cross-checked against rpm 4.20's `rpm.vercmp` on 30,091 version
pairs taken from the repodata plus rpm's own test vectors: identical.

**What it takes for a fully Rocky-native glibc buildroot.** 328 binary RPMs
from 199 SRPMs must exist (built by us) to reproduce mock's glibc buildroot
exactly. Following BuildRequires transitively (every SRPM needed to build every
buildroot SRPM, to a fixpoint) reaches **1120 of the 2217 SRPMs** in
BaseOS+AppStream+CRB -- essentially the self-hosting core of the distribution
(toolchains, perl/python/ruby/java/texlive documentation stacks, ...). That is
an upper bound: many of those edges are doc/test-only BRs that a bootstrap can
cut with `--without`/`--nocheck`-style options, and cycles are broken by
stage0.

**Unresolved deps** in that recursive closure are almost all *buildroot-only*
packages that Rocky ships only in the `devel` repo (e.g. `libeconf-devel`,
`gi-docgen`, `perl(Test::Needs)`, `libblockdev-*-devel`). Generating a scratch
lock with `--repos BaseOS AppStream CRB devel` (devel is 70 MB of primary
metadata; 2431 SRPMs, 8380 binaries) leaves only 3 SRPMs with unresolved BRs
(`gcc`, `gcc-toolset-15-gcc`, `gnu-efi`: all need the i686 `glibc32` /
`glibc-devel(x86-32)` that is in no x86_64 repo), and the recursive closure
grows to 1211 SRPMs. glibc itself needs nothing from devel.

**Known approximations** (see the `tools/resolve-buildrequires.py` docstring):
arch-conditional BRs are whatever the SRPM header recorded on Rocky's build
host; `%generate_buildrequires` (dynamic BRs, used by many python/rust/go
packages) is invisible in repodata; file deps outside primary.xml's file subset
(`/etc/*`, `*bin/*`, `/usr/lib/sendmail`) are not resolvable without
filelists.xml; Conflicts/Obsoletes are reported, not enforced (none are hit by
glibc's buildroot).
