# E1: DWARF prefix map (WP0a)

Question (design §9): does `-ffile-prefix-map` remove all input store paths
from the DWARF of a relocated glibc, including ld.so's retained DWARF?

**Verdict: PASS.** The relocated glibc built through `nn.cc.stage0` (cc-wrapper
with the `add-prefix-map.sh` hook, environment `-frandom-seed` dropped)
references only itself; no full or pieced input store path anywhere in the
699 MB output (14 255 files, 1 416 `.debug` files, `.dwz`, ld.so); ld.so's
DWARF strings are byte-identical to the milestone-1 FHS build.

The §5.1 hook shape as first written ("every `-isystem`/`-idirafter` input
root") was **not** sufficient in general: the first E1 pass depended on a
3-character margin (review finding, see "Review fixes" below). gcc names a
header found in a *system* include dir by its realpath whenever that is
shorter, so a symlink-farm include root leaks its targets' store paths.
The hook now maps every input (`NIX_ROCKY_MAP_ROOTS`, filled by the
wrapper's setup hook), every store path named on the command line, and the
symlink targets of store system include dirs; E1 was rebuilt with it.

## Setup

* Recipe: `lib/rocky/cc/e1-glibc.nix` (`nn.cc.e1.glibc`). It is the [NF-S3]
  spike `spikes-nixpkgs-faithful/glibc-reloc.nix` (rpmbuild outside the FHS
  chroot, `%_prefix = $out`, one output, bwrap tool shim, `--with-headers`
  spec substitution to the Rocky kernel-headers tree, P1 as sed) with three
  changes:
  1. compiler = `nn.cc.stage0` = `nn.cc.wrap { libc = nn.cc.stage0Libc; }`
     (`lib/rocky/cc/wrap.nix`) instead of the spike's `ccwrap.nix`;
  2. `%_usrsrc /usr/src` (design §1.2) instead of `$out/src`;
  3. inputs from this flake (no `builtins.getFlake`).
* The hook (`lib/rocky/cc/add-prefix-map.sh`, the wrapper's
  `nix-support/cc-wrapper-hook`) adds `-ffile-prefix-map=<root>=/usr` for the
  gcc copy and for every store root named by `-I -iquote -isystem -idirafter
  -cxx-isystem` (joined or separate; `<root>/usr` for FHS-in-store trees such
  as the kernel-headers RPM tree), and drops `-frandom-seed=*` from what the
  environment injected. In this build the environment carried
  `NIX_CFLAGS_COMPILE= -frandom-seed=3nfqdah0h9 -isystem <30 nixpkgs tool include dirs> -isystem <glibc-build-deps-hoisted>/include`
  (nixpkgs `reproducible-builds.sh` + cc-wrapper setup hook, as in the spike).
* Scanner: `lib/rocky/cc/storescan.py` (stdlib; ELF sections decoded:
  SHF_COMPRESSED zlib/zstd, `.zdebug_*`, xz `.gnu_debugdata`). It reports every
  `/nix/store/<hash>` whose hash is not the output's own (full), and every
  8-byte window of an input hash outside a full occurrence (pieced, as
  `fragscan.py` does for the own prefix). Inputs = the 113 store paths the
  derivation could have leaked: its direct inputs (all nixpkgs tools, rpm,
  debugedit, texinfo, macros, SRPM) plus the wrapper's components (gcc copy,
  binutils copy, stage0Libc, bintools wrapper) and the stage0 originals.
  Sensitivity checked on a synthetic file (full path + a lone 12-char window
  of an input hash: both reported) and on an object built with `-gz=zlib`
  whose comp dir was mapped to a store path (found in the compressed
  `.debug_line_str`).

## Observations

* gcc canonicalises its relocated include dirs
  (`<gcc>/bin/../lib/gcc/...` -> `<gcc>/lib/gcc/...`) before remapping, so the
  single map `<gcc copy>=/usr` yields Rocky's `/usr/lib/gcc/x86_64-redhat-linux/14/include`.
* The FHS-in-store kernel-headers tree needs `<root>/usr=/usr` (else
  `/usr/usr/include`); the hook emits those after the plain maps because gcc
  applies the last matching map.
* The map cannot tell *which* input a header came from: a header picked up
  from an undeclared nixpkgs `-dev` output (30 of them are on the
  `-isystem` list in this spike-shaped build, through the cc-wrapper setup
  hook of every native input) would also read `/usr/include/...`. DWARF stops
  being evidence of build purity; that job stays with the declared-input view
  (§1.5, E2/WP3) and the purity assertion (§7.3). (glibc compiles itself with
  `-nostdinc`, and its ld.so/libc DWARF is identical to the chroot build's.)
* `-grecord-gcc-switches` does not record `-ffile-prefix-map`, `-I`,
  `-isystem`, `-idirafter`, `-D` (tested), so neither maps nor include roots
  leak into DW_AT_producer; `-frandom-seed` *is* recorded, hence the drop.
  A `-frandom-seed` passed by the build itself is kept (Rocky would see it).
* Pieced windows of *input* hashes: none. (The pieced `$out` windows in
  ld.so/ldconfig/localedef [F-2] are the output's own prefix, not inputs.)

## Review fixes (cc-fix): what the first pass missed, and the rebuilt E1

### 1. Symlink-farm include roots (the 3-character margin)

gcc's libcpp names a header found in a **system** include dir (`-isystem`,
`-idirafter`, default dirs) by `lrealpath(header)` whenever that string is
shorter (`-fcanonical-system-headers`, `maybe_shorter_path`). If the root is
a symlink farm, the shorter name is the *target's* store path, and the first
hook only mapped the roots named on the command line. In this E1 build
`glibc-build-deps-hoisted` (`cp -rs` of the FHS tree `stage0-glibc-build-deps`)
is such a farm, named as `-isystem` by the cc-wrapper setup hook:

```
86 /nix/store/45jz8wd3…-glibc-build-deps-hoisted/include/sys/sdt.h
-> 89 /nix/store/451v3lam…-stage0-glibc-build-deps/usr/include/sys/sdt.h
```

The link is 3 characters shorter than its target, so gcc kept the link (mapped).
A hoisted name 4 characters longer would have put `451v…/usr/include/sys`
into the DWARF unmapped. Fix in `add-prefix-map.sh`:

* **every input**: the wrapper's setup hook (`lib/rocky/cc/map-roots.sh`,
  `addEnvHooks` for all three host offsets) exports `NIX_ROCKY_MAP_ROOTS` =
  every dependency of the stdenv build, propagated ones included; the hook
  maps each one (and `<root>/usr` when `<root>/usr/include` exists). This is
  what design §0.2 #13 asks for ("for every input"). It also covers
  `#include "/nix/store/…"` of a declared input.
* **symlink targets of named system include dirs**: for each store
  `-isystem`/`-idirafter`/`-cxx-isystem` root, the store roots its symlinks
  resolve to are mapped too (`<root>/usr` for targets under `usr/include`).
  These need not be inputs: `451v…` is only in the farm's closure. The walk
  uses bash globstar and coreutils `realpath`, because the wrapper's PATH is
  only coreutils and grep. It runs once per root and build and is cached in
  `$TMPDIR/.rocky-cc-linkroots/<root name>`, written atomically. Writable
  roots (the build's own outputs) are not walked.
* **named files**: `-include`/`-imacros` arguments and source files in the
  store are mapped (review finding 4).

Cost: ~2 ms per compile with a warm cache (trivial `gcc -c`, 50 roots in
`NIX_ROCKY_MAP_ROOTS`, kernel headers as `-isystem`: 18.5 vs 16.3 ms, and
20.5 vs 18.7 ms in a second run on a shared machine). The first (uncached) walk
of the kernel-headers tree (1 015 files) adds about 20 ms (cold 33–38 ms vs
warm 17–18 ms for the same compile), once per build.

`checks.nn-cc-toolchain` now has the regression case. A farm named
`include-farm-of-symlinks-with-a-rather-long-name-for-the-nn-cc-check` links
to the short-named `rh` (plain) and `rf` (FHS `usr/include`, like sdt.h);
link 133 characters, target 67. As a control, the unwrapped gcc with only
the farm mapped writes both target store paths into the line table. Through
the wrapper there are no store paths and the table reads `/usr/include`,
never `/usr/usr`. This holds for `-isystem DIR`, `-isystemDIR` and
`-idirafter` and with a cold or warm cache. Further cases: `-include
<store>/x.h`, a store source file (`__FILE__` reads `/usr/rocky-src.c`), and
an absolute `#include "<store>/…"`. That last one stays in the DWARF unless
its root is in `NIX_ROCKY_MAP_ROOTS` (control), and is clean when it is.

## The same hook on small programs (WP4, `checks.nn-cc-toolchain`)

gives `/nix/store/ypi49g6jxkqsycx24kldzzf3gjib3n9g-nn-cc-toolchain`: 148
PASS, 0 FAIL, and `--rebuild` is byte-identical. The wrapper, bintools
wrapper and binutils copy also pass `--rebuild`.

* Part A runs in the stdenv environment, with `-frandom-seed` in
  `NIX_CFLAGS_COMPILE` and `NIX_ENFORCE_PURITY=1`. It builds C, C++, a
  shared lib, `-m32`, `-static`, `-flto` and slim-LTO archive programs. It
  also covers the prefix-map cases from 1, version probes that get no maps
  (asserted on `NIX_DEBUG` output, with a compile as control), and
  `-I/usr/…`, `-L/usr/lib64` and `-rpath /usr/lib64` kept under purity,
  including a bwrap `/usr` view where the program builds and runs.
* Part B runs from PATH with an empty environment and Rocky's flags, and
  includes slim LTO with plain `ar`/`nm`.
* Part C uses a libc split into out/dev and checks a subset of A/B:
  crt/libc locations, PT_INTERP, RUNPATH store entries, no RPATH,
  PIE/BIND_NOW/RELRO, the producer, runs (`-m32` with no fallback) and
  DWARF.

## Not done

* `fragscan.py` itself was not used: it only looks for pieces of the
  scanned tree's *own* prefix; `storescan.py` does the same windowing for the
  input hashes (and reports full foreign paths, decoding compressed sections).
* E1 still uses the spike recipe (stdenv tool inputs, hoisted farm), not
  mkRpmPackage and the declared-input view.
