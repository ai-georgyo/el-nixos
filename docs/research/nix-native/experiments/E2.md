# E2: declared-input `/usr` view + `$out` self-prefix alias

Question (docs/nix-native-design.md §9 E2, §1.5): do the tool shim's `/usr`
view of the *declared* inputs and the `$out` self-prefix alias keep relocated
builds identical, and do they make spec substitutions such as glibc's
`--with-headers=%{_prefix}/include` unnecessary?  Decides the default of
`prefixView`.

**Verdict: `prefixView = true` by default, under four conditions.**  The
first is implemented here; the other three go to other work packages:

1. the view is made of **real directories** (read-only overlayfs of the
   inputs' dirs), not a symlink farm — glibc's configure rejects a symlinked
   `$prefix/include/scsi` (implemented in `tool-shim.sh`, tested by
   `checks.nn-shim`);
2. while rpmbuild runs, the cc-wrapper maps **`-ffile-prefix-map=$out=/usr`**
   (WP4/E1): headers reached through the alias are otherwise recorded in DWARF
   as `$out/include/...` — dangling self-references (glibc: 8 files, all
   DWARF, one masked as "backed"; krb5: `$out/include/et`);
3. **library rule** (WP6): every declared view input that provides shared
   libraries is also a cc-wrapper input.  A library that the build reaches
   only through the view links fine and runs inside the shim, but fails outside it
   (`cannot open shared object file`, rc 127): see "Library hazard" below.  It
   gets there through `-L%{_libdir}` (the alias) or through ld's built-in
   `SEARCH_DIR("=/usr/lib64")`, which Rocky's binutils has and the S1 gcc
   (`no-sys-dirs`) does not remove.  With the rule followed, the probe's
   outputs work; `-L%{_libdir}` then still adds a dangling `$out/lib64`
   RPATH entry, which `ROCKY_PREFIX_VIEW_DIRS="include libexec share"` (alias
   without lib/lib64, new in the shim) removes, at the cost of specs that
   read `%{_libdir}/xxxConfig.sh` or `%{_libdir}/pkgconfig` (krb5);
4. **NEEDED guard** (WP5): resolve every `DT_NEEDED` against RUNPATH and the
   loader's dirs and fail on what does not resolve; the `$out/<rel>` string
   scan cannot see this class of leak.  Prototype: `scan_needed` in
   `lib/rocky/e2/compare.py`.  It found real bugs here that have nothing to
   do with the view (finding 10).

Evidence (re-run 2026-10-18 with the fixed shim):
- glibc builds from the **unmodified** spec (`--with-headers=%{_prefix}/include`
  resolves through the alias) with identical file lists and identical
  code/data; the only differences are 8 non-loaded-DWARF files.
- **krb5** is a real SRPM that reaches build deps through
  `source %{_libdir}/tclConfig.sh` and `-I%{_includedir}/et`.  It builds
  unmodified with the view; noview needs the `tclConfig.sh` substitution.
  The two outputs have identical stripped binaries and configure results;
  the differences are listed in the krb5 section.
- The six small SRPMs are identical apart from build-ids.  That result is
  weak evidence: in all six, every view input was also a cc-wrapper input or
  a PATH tool, and none needed a substitution without the view.
- Two probes show the view does its job, and they map where the
  string-reference scan stops and the NEEDED guard is needed.

`prefixView = false` + `specSubstitutions` stays as the per-package fallback.

## Setup

Code: `lib/rocky/e2/` (experiment only), the shim itself:
`lib/rocky/tool-shim.sh`, `lib/rocky/mkview.py`, `lib/rocky/parts/toolShim.nix`
(test: `checks.nn-shim`).

* `reloc.nix`: one SRPM built by rpmbuild **outside** the FHS chroot, relocated
  to `%_prefix = $out`, nixpkgs cc-wrapper over the stage0 toolchain, tools from
  PATH, stage0 rpm 4.19 + Rocky macro packages as `/usr/lib/rpm` — the
  [NF-S3] recipe (`spikes-nixpkgs-faithful/glibc-reloc.nix`), generalised, run
  through `nn.toolShim` in two variants that differ **only** in the shim:
  * `noview`: `/usr` = PATH tools (`bin`, `sbin -> bin`) + `/usr/lib/rpm`, no
    alias — exactly the [NF-S3] shim;
  * `view`: additionally the declared inputs' `include lib lib64 libexec share`
    under `/usr` and the same view read-only at `$out` (`ROCKY_PREFIX_VIEW=1`;
    `aliasDirs` -> `ROCKY_PREFIX_VIEW_DIRS` limits what the alias shows).
  Declared inputs = the SRPM's library inputs (all of `dev`/`out`/`lib` of the
  nixpkgs stand-ins) + its BuildRequires tool packages; generic stdenv tools are
  PATH-only.  Library inputs also go to the cc-wrapper (`buildInputs`) in both
  variants, except where a probe says otherwise.  `specSubstitutions` apply to
  noview only, `commonSubstitutions` to both (relocation fixes unrelated to
  the view).  `outsideRun`: shell run after the payload is in `$out`, outside
  the shim (`nix-support/run-outside.txt`).
* Same store name in both variants (same `$out` length), one fixed gcc random
  seed (`NIX_OUTPATH_USED_AS_RANDOM_SEED`), so outputs are byte-comparable
  modulo the own store hash.  The payload is the whole rpm BUILDROOT under
  `$out` (no partition).  The rpmbuild log goes to the builder's stderr
  (`nix log`); `$out` keeps only `nix-support/build-summary.txt`, the cited
  lines normalised and sorted, so outputs are reproducible
  (`nix build --rebuild .#nn.toolShim.e2.which.view` passes; before, the
  copied build.log differed in `rpm-tmp.*` names and `Wrote:` order).
* `compare.py`:
  - relative file lists (`.build-id` links keyed by target);
  - contents classified identical / modulo own hash / modulo pieced hash runs
    / modulo build-id (ELF32/64, section by section; MiniDebugInfo
    decompressed) / modulo ar dates / DWARF-ONLY (only non-loaded `.debug_*`
    sections differ) / DIFFERS; symlink targets;
  - a reference scan of every file (raw, gzip members, compressed ELF
    sections, MiniDebugInfo): each `$out/<rel>` is *backed* (exists in the
    output), **DANGLING-IN-VIEW** (no file of the build, but present in the
    build's view — a compiled-in reference into the view), or *dangling*;
    plus references to other store paths;
  - **new: NEEDED resolution.**  Each `DT_NEEDED` soname of every ELF file
    (`lib/debug` excluded) is looked up in DT_RUNPATH (else DT_RPATH,
    `$ORIGIN` expanded) and in the program interpreter's directory (for a
    library: every interpreter the tree's programs use).  A soname found
    nowhere is **UNRESOLVED-NEEDED**.  The interpreter-directory rule
    approximates the loader's default path: it is exact for a relocated glibc
    (slibdir = its own lib64), while stage0's FHS ld.so would search
    `/usr/lib64`, which a Nix host does not have.

```
nix build -L --cores 6 --max-jobs 2 .#checks.x86_64-linux.nn-shim
nix build --cores 6 --max-jobs 2 .#nn.toolShim.e2.{which,xz,gzip,sed,m4,expat,probe,probeLib,krb5,glibc}.compare
python3 -I lib/rocky/e2/compare.py OUT <nf-s3 glibc> <noview glibc>     # determinism control
nix build --rebuild .#nn.toolShim.e2.which.view                         # output reproducibility
```

none of the specs needs a substitution without the view.  "Identical apart
from build-ids" was close to guaranteed.  Only glibc, krb5 and the two
probes test the alias.

## Positive control: headers through the view (`probe`)

`lib/rocky/e2/probe/e2probe.spec`: a declared input that is NOT a cc-wrapper
input, reached only via `%{_includedir}/e2probe-dep`, `%{_libdir}/pkgconfig`
and `/usr/include/...`:

```
noview                                   view
missing include/e2probe-dep/...h         found   include/e2probe-dep/...h
missing lib64/pkgconfig/e2probe-dep.pc   found   lib64/pkgconfig/e2probe-dep.pc
missing /usr/include/e2probe-dep/...h    found   /usr/include/e2probe-dep/...h
found   /usr/bin/true /bin/sh /usr/bin/perl (both)
compiled-with-dep no                     compiled-with-dep yes
```

The string scan fires: `+ DANGLING-IN-VIEW $P/include/e2probe-dep <-
lib/debug/.../e2probe-...debug` (`.debug_line_str` names the header's
directory under `$out`, where no file of the build lives).  So the view does
what it is for, and a header reached through the alias shows up as a
dangling self-reference in DWARF.  That scan is **not** enough for libraries,
as the next section shows.  (The first version of this report said
"anything it lets leak into an output is caught"; that was wrong.)

## Library hazard (`probeLib`, review finding)

`lib/rocky/e2/probelib/e2probelib.spec` links `libe2lib.so` (declared view
input `e2probelib-dep`, `lib64/libe2lib.so`) two ways:
- `libdir`: `-L%{_libdir} -le2lib`, i.e. through the alias `$out/lib64`;
- `builtin`: `-le2lib` with no `-L`, i.e. through ld's built-in search.

Stage0 ld's `ld --verbose` lists:

```
SEARCH_DIR("=/usr/x86_64-redhat-linux-gnu/lib64") SEARCH_DIR("=/usr/lib64") SEARCH_DIR("=/usr/local/lib64")
SEARCH_DIR("=/lib64") SEARCH_DIR("=/usr/x86_64-redhat-linux-gnu/lib") SEARCH_DIR("=/usr/local/lib") SEARCH_DIR("=/lib") SEARCH_DIR("=/usr/lib")
```

Inside the shim, `/usr/lib64` is the view.  Each program runs inside the
build (what a `%check` would see), and `outsideRun` runs the installed copy
again outside the shim.  Report: `e2-compare-e2probelib`, every variant
against `noview-wrap`:

| variant | dep is cc-wrapper input | alias dirs | links | runs inside | runs outside | RPATH (libdir / builtin) | NEEDED guard | string scan |
|---|---|---|---|---|---|---|---|---|
| noview-wrap | yes | — | both | both | both rc 0 | `$out/lib:<dep>/lib64:libc:gcc` (both) | 0 | — |
| view-wrap | yes | all | both | both | both rc 0 | libdir: `$out/lib:$out/lib64:<dep>/lib64:…`; builtin: as noview | 0 | `DANGLING-IN-VIEW $P/lib64` (libdir) |
| view-nowrap | no | all | both | both | **both rc 127** `libe2lib.so: cannot open shared object file` | libdir: `$out/lib:$out/lib64:libc:gcc`; builtin: `$out/lib:libc:gcc` | **2 UNRESOLVED-NEEDED** | only `$P/lib64` (libdir); nothing for builtin |
| view-wrap-nolibalias | yes | include libexec share | both | both | both rc 0 | as noview | 0 | — (identical to noview modulo build-id) |
| view-nowrap-nolibalias | no | include libexec share | both | both | **both rc 127** | `$out/lib:libc:gcc` (both: `-L$out/lib64` does not exist, ld falls through to `=/usr/lib64`) | **2 UNRESOLVED-NEEDED** | nothing |

Conclusions:
- The failure is silent during the build: it links, and it runs inside the
  shim because the stage0 ld.so also searches `/usr/lib64` = the view.
  With the S1 relocated glibc, whose loader does not search `/usr/lib64`, a
  `%check` would at least fail inside.
- The string scan cannot see it.  The `builtin` link leaves no `$out` string
  at all, and a `$out/lib64` RPATH counts as "backed" whenever the package
  ships its own lib64.
- What avoids it is the library rule: as a cc-wrapper input, the dependency's
  real `-L` is searched before ld's built-in dirs and lands in RUNPATH.
  Hiding lib/lib64 from the alias does not help on its own: `=/usr/lib64`
  still reaches the view.
- With the rule followed and a full alias, the only remaining effect is a
  dangling `$out/lib64` RPATH entry; `ROCKY_PREFIX_VIEW_DIRS` without lib
  dirs, or a patchelf `--shrink-rpath` style fixup, removes it.
- The NEEDED guard flags every broken binary and nothing else.

## A real SRPM through `%{_libdir}` / `%{_includedir}`: krb5

`krb5-1.21.3-10.el10_2`'s `%build` starts with `source %{_libdir}/tclConfig.sh`
and `INCLUDES=-I%{_includedir}/et`.

Declared view inputs (31 store paths):
- tcl, in Rocky's layout (`lib64/tclConfig.sh`);
- e2fsprogs com_err/ss: stage0-libc copies with their `.pc` files;
- openssl, keyutils, libselinux, pam, libverto, openldap, lmdb, libedit,
  ncurses;
- the BuildRequires tools.

Library inputs are cc-wrapper inputs in both variants.

Stand-ins the nixpkgs world needed, identical in both variants and unrelated
to the view:
- compile_et/mk_cmds made from Rocky's e2fsprogs source (nixpkgs does not
  install them);
- a `<openssl/fips.h>` stand-in (a RHEL openssl-devel addition that krb5's
  RHEL patches include);
- an `autoreconf` stand-in (`autoconf --force && autoheader --force`).
  nixpkgs has autoconf 2.69, which is too old for the spec's
  `--runstatedir`, and 2.73, whose autoreconf rejects krb5's `K5_AC_INIT`
  with "AC_INIT not found".  Rocky has 2.71;
- `getconf`;
- systemd dir macros.

Results:
- `noview` needs one substitution: `source %{_libdir}/tclConfig.sh` ->
  `source <tcl>/lib64/tclConfig.sh`.  The `et` headers also come from
  `com_err.pc`, so `-I%{_includedir}/et` pointing nowhere is harmless.
- `view` builds the **unmodified** spec: tclConfig.sh is sourced through the
  alias.
- Both need one relocation fix in common (finding 9).

`e2-compare-krb5` (noview = A, view = B):

| | |
|---|---|
| entries | 4194 vs 4194, none only in one |
| identical / modulo own hash / modulo pieced hash / gzip modulo hash | 3518 / 141 / 1 / 1 |
| modulo build-id (all stripped binaries and libraries) | 72 |
| DIFFERS | 4, none in a shipped binary (below) |
| configure results (354 `ac_cv`/`k5_cv` cache variables in the shipped config.log) | identical |
| unbacked `$out` refs new in view | 0 by the A/B diff; the view build has `DANGLING-IN-VIEW $P/include/et` (DWARF; same class as glibc) and `$P/share/info` (config.log) |
| unresolved NEEDED new in view | 0 (134 in both: finding 10) |
| collisions between view inputs | 1 `dir-vs-file lib/pkgconfig` (openssl-dev's dir hides the python env's symlink) |

The 4 DIFFERS files:
- the `.debug` files of `kvno` and `libkrb5.so.3.3`: `.symtab`/`.strtab`
  (LTO local-symbol suffixes such as `kvno.c.d532f24a`) and DWARF;
- `share/doc/krb5-workstation/searchindex.js`: sphinx indexes the own store
  hash as a search term and sorts its terms, so the hash moves (sorted token
  diff: only the hash);
- `share/krb5-tests/x86_64/config.log`: LTO temp file names
  (`/build/ccXXXXXX.ltrans0.ltrans.o`), 22 lines.

To tell noise from view effects, krb5 noview was also rebuilt against
itself (`nix build --rebuild`).  The build is not bit-reproducible: only the
shipped `config.log` differs (LTO temp names), and the other 3736 files are
identical, including both `.debug` files and `searchindex.js`.

So of the 4 view-vs-noview differences:
- `config.log` is build noise;
- `searchindex.js` follows from the different `$out` hash, as it would
  between any two store paths;
- the two `.debug` files are a **view effect**, confined to unloaded debug
  files.  Their DWARF names `$out/include/et` (condition 2), and the LTO
  local-symbol suffixes change with it.

Not verified: whether `-ffile-prefix-map=$out=/usr` also equalises those
suffixes.

`view-etviewonly` (e2fsprogs only in the view, not a cc-wrapper input) does
**not build**.  With no `com_err.pc` on `PKG_CONFIG_PATH`, configure takes
its `-lcom_err` fallback and libprofile is linked without it (`undefined
reference to add_error_table`, `--no-undefined`).  So in this real spec the
missing-wrapper-input case fails loudly; the silent case is the probe's.

first run):

| | |
|---|---|
| entries | 17042 vs 17042, none only in one |
| identical | 12582 |

The 8 DWARF-ONLY files:
- `lib64/ld-linux-x86-64.so.2` and its sysroot copy (ld.so keeps DWARF);
- `lib/debug/.dwz/glibc-…`;
- the `.debug` files of `libc.so.6`, `libc_malloc_debug.so.0` (and its
  sysroot copy), `ldconfig` and `makedb`.

The differing bytes are include-directory names in
`.debug_line`/`.debug_line_str` (and the offsets into them in `.debug_info`):

```
noview: /nix/store/<h>-rpm-kernel-headers/usr/include/{linux,asm-generic}
        /nix/store/<h>-glibc-build-deps-hoisted/include/{sys,selinux}
view:   /nix/store/<h>-glibc-2.39-142.el10_2/include/{linux,asm-generic,sys,selinux}
```

glibc compiles with `-isystem $sysheaders`, which is now the alias, and
evidently searches it before the cc-wrapper's `-isystem` of the build deps.
So sdt.h and the selinux headers are found there too (the same files: the
view contains glibcBuildDeps).

In the no-view build these names are *input* store paths (a closure leak
that E1's prefix map removes).  In the view build they are *self* references
that no file backs.  `include/sys` is reported "backed" only because glibc
ships an `include/sys/` directory: DWARF's directory table names the
directory and the file entry `sdt.h` separately, so this dangling reference
is invisible at directory granularity.

Hence condition 2 of the verdict: `-ffile-prefix-map=$out=/usr` during
rpmbuild turns all of them into `/usr/include/...`, which is what Rocky's own
DWARF says.  It is safe because nothing but the view lives under `$out`
while rpmbuild runs.

**Determinism control** (by hand, since the [NF-S3] build is a store path
literal): `compare.py <NF-S3 nncpaslng…> <noview>` with this run's noview.
- 17042 entries in both, 12547 identical, 724 modulo build-id, 16 modulo
  hash, 733 DWARF-ONLY, 0 DIFFERS, no new unbacked refs or unresolved
  NEEDED.  These are the same numbers as with the first run's noview.
- The 733 come from the gcc random seed.  [NF-S3] ran nixpkgs'
  reproducible-builds hook seeded with its own `$out`
  (`-frandom-seed=nncpaslng9` in `DW_AT_producer`); E2 fixes the seed for
  both variants.  That string changes `.debug_str` and every `.debug_info`
  offset into it.
- So the [NF-S3] shim and `nn.toolShim` without inputs produce the same
  glibc, and the view adds exactly the 8 DWARF-ONLY files above.

## Findings along the way (fed to other work packages)

1. **The view must be real directories, not a symlink farm.**
   - The first glibc `view` attempt failed in configure.
     `sysdeps/unix/sysv/linux/configure` checks
     `test -L ${prefix}/include/{net,scsi}` ("'make install' will destroy
     the target of the link(s)"), and the symlink view had
     `$out/include/scsi -> <kernel-headers>/usr/include/scsi`.
   - The shim now mounts `include lib lib64 libexec share` as read-only
     **overlayfs** of the inputs' directories (bwrap
     `--overlay-src`/`--ro-overlay`, the lib/chroot.sh mechanism; first
     input = topmost; one input = a bind), on a tmpfs at `/usr` and at
     `$out` that is remounted read-only.
   - Only `bin` stays a symlink farm (PATH tools).  `checks.nn-shim` asserts
     real dirs/files and that they are read-only.
2. **DWARF names view files by their `$out` path.**
   - A header reached through the alias is recorded as `$out/include/...`
     (positive control; glibc kernel headers; krb5 `include/et`).
   - E1's `-ffile-prefix-map=<input>=/usr` does not cover those.  With
     `prefixView`, the cc-wrapper hook must also map
     `-ffile-prefix-map=$out=/usr` while rpmbuild runs.  That is safe,
     because during rpmbuild nothing but the view lives under `$out` (the
     shim enforces `$out` empty before and after).
3. `config.site` must end with status 0: autoconf >= 2.70 aborts with "failed
   to load site script" when the last `test ... && x=...` did not match
   (which's configure passes `--sharedstatedir=/var/lib`).  Design §1.3's
   snippet has this bug (trailing `:` fixes it).
4. **Macro files in `/usr/lib/rpm/macros.d/` lose against the platform
   file.**
   - rpm 4.19's macro path is `macros : macros.d/macros.* :
     platform/%{_target}/macros : fileattrs : redhat/macros :
     /etc/rpm/macros.* : ...`.
   - `platform/x86_64-linux/macros` defines `%_prefix %_exec_prefix %_bindir
     %_sbindir %_libexecdir %_datadir %_sysconfdir %_sharedstatedir
     %_localstatedir %_lib %_libdir %_includedir %_oldincludedir %_infodir
     %_mandir %_initddir %_rundir %_defaultdocdir %__spec_install_pre
     %__arch_install_post %__brp_* %__os_install_post %__spec_install_post`.
     So design §1.2's `macros.d/macros.zz-nix-reloc` would be silently
     overridden for exactly the relocation macros.
   - Measured in the shim (stage0 rpm 4.19.1.1, Rocky macro packages) with
     `macros.d/macros.zz-e2` = `%_prefix /e2/macros.d`, `%_sysconfdir /e2/etc`,
     `%e2_marker set`, and `%_libdir /e2/redhat/lib64` appended to
     `redhat/macros`.  `rpm` and `rpmbuild`, with and without `--target
     x86_64`, all print `_prefix=/usr _sysconfdir=/etc
     _libdir=/e2/redhat/lib64 e2_marker=set`: the file IS read, and the
     platform file wins.
   - `rpmbuild --load FILE` is **dropped** when `--target` re-reads the
     configuration.  Seen with sed: `rm -rf $RPM_BUILD_ROOT` left
     unpackaged `/usr/src/debug/*` because the realias in
     `__spec_install_post` never ran.
   - What works: `--define` (single line, as [NF-S3]), appending to the
     build's copy of `redhat/macros` (E2), or a file in `/etc/rpm/` (would
     need a bind in the shim).
5. `check-rpaths` (`%__arch_install_post`) rates every absolute RUNPATH outside
   `/lib*`, `/usr/lib*` as "invalid" (0x0002) and fails the build: store
   RUNPATHs need `QA_RPATHS=0x0002` (design §5.5 says "not needed": wrong).
6. Rocky tool names the specs/macros call: `/sbin/ldconfig` (redhat
   `brp-ldconfig`; glibc's spec disables it), `gpgv2` (`%gpgverify`),
   `getconf` (krb5).  With the shim they are just PATH entries
   (`/sbin -> usr/bin`).
7. **S1 hazard: nixpkgs libraries in stage0-libc programs.**
   - nixpkgs libraries linked into binaries that use the stage0 libc 2.39
     pull in nixpkgs glibc 2.42's `libdl.so.2`/`libpthread.so.0` through
     their RUNPATH.  Those stubs need `GLIBC_ABI_DT_X86_64_PLT`, so the
     program (sed/sed, run by help2man; krb5 configure's libss test) does
     not start.
   - E2 used RUNPATH-patched copies (`forStage0Libc`) for acl, libselinux
     and e2fsprogs.
   - `stage0.glibcBuildDeps`' version check would not catch it: it skips
     nixpkgs glibc itself and compares `GLIBC_2.x` versions only.  It was
     harmless there because nothing linked against those libraries runs
     during the glibc build.
8. nixpkgs' reproducible-builds hook seeds gcc with `$out`'s hash: the seed
   lands in `DW_AT_producer` (`-grecord-gcc-switches`) and changes the order of
   `.debug_str`, so two builds with different `$out` differ in DWARF beyond the
   path — another reason for design §5.1's "hook off" (E2 fixed the seed).
9. **Relocation hazard: the package name in `$out`.**  krb5 defines
   `libsdocdir` as `%{_pkgdocdir}` piped through `sed -e
   s,krb5,krb5-libs,g`.  That replaces *every* "krb5", including the one in
   `/nix/store/<h>-krb5-1.21.3-…`, so `%install`'s
   `rm $RPM_BUILD_ROOT/%{_docdir}/krb5-libs/examples/kdc.conf` fails.  This
   has nothing to do with the view: with `%_prefix` under a store name that
   contains `%{name}`, any spec that edits paths by package name needs a
   per-package fix (here `s,krb5$,krb5-libs,`).
10. **The NEEDED guard finds broken binaries the view did not cause** (same
    in noview and view):
    - glibc: `bin/memusagestat` (libgd, libpng16, libz) and `bin/makedb`
      (libselinux) have no RUNPATH, because [NF-S3]'s recipe sets
      `NIX_DONT_SET_RPATH=1`;
    - xz (`liblzma.so.5` for `xz`, `xzdec`, `lzmadec`, `lzmainfo`), expat
      (`libexpat.so.1` for `xmlwf`), and krb5 (134 pairs: every library and
      program needing krb5's own libraries).  The nixpkgs ld-wrapper's
      self-RPATH is `$out/lib`, but Rocky's `%{_libdir}` is `$out/lib64`.
      On Rocky, `/usr/lib64` is the loader's default path; relocated, the
      own `%{_libdir}` (after the partition: the owning output's lib64)
      must go into RUNPATH (WP4/WP6), and WP5's guard must check it.
11. Once (krb5's first attempt), `%autosetup -S git_am` failed with `error:
    invalid object … for 'src/clients/kdestroy/kdestroy.c'` / `git
    write-tree failed`.  The same patches apply cleanly outside the build,
    and the identical derivation's next attempt passed.  Not investigated
    further; noted as flaky.

## Shim changes from the review

- **One view per call.**  `mkview.py` no longer `rmtree`s a shared
  `$NIX_BUILD_TOP/rocky-view`.  The shim plans each call's view in its own
  `mktemp -d $NIX_BUILD_TOP/rocky-view.XXXXXX` and removes it when the call
  ends; `mkview.py` refuses a non-empty directory.
  - Before, a nested call emptied the outer namespace's `/usr/bin`.  The new
    `checks.nn-shim`, run against the reviewed shim (4c06274), fails with
    `nested call changed the outer /usr/bin (188 0)`.
  - The collision report is written only to `ROCKY_VIEW_COLLISIONS` (per
    call; otherwise just a summary on stderr).
  - `ROCKY_PREFIX_VIEW` and `ROCKY_VIEW_COLLISIONS` are unset inside, so a
    nested call does not re-alias the read-only `$out` and does not
    overwrite the caller's report.
- **`PWD=/`**: `/` is no longer bound over the tmpfs root (`bwrap: Can't make
  symlink at /bin`); `--chdir /` works.
- **`ROCKY_PREFIX_VIEW_DIRS`**: which input dirs the alias shows (default
  all; `bin` always).
- coreutils by absolute path in the shim (`@coreutils@`).

All of the above is covered by `checks.nn-shim` (nested, concurrent, report
kept, nothing left in the build top, `PWD=/`, alias dirs, nested call inside
the alias).
