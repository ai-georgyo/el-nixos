# E2: declared-input `/usr` view + `$out` self-prefix alias

Question (docs/nix-native-design.md §9 E2, §1.5): do the tool shim's `/usr`
view of the *declared* inputs and the `$out` self-prefix alias keep relocated
builds identical, and do they make spec substitutions such as glibc's
`--with-headers=%{_prefix}/include` unnecessary?  Decides the default of
`prefixView`.

**Verdict: `prefixView = true` by default**, with two conditions that are
now part of the mechanism / handed to other work packages:

1. the view is made of **real directories** (read-only overlayfs of the
   inputs' dirs), not a symlink farm — glibc's configure rejects a symlinked
   `$prefix/include/scsi` (implemented in `tool-shim.sh`, tested by
   `checks.nn-shim`);
2. while rpmbuild runs, the cc-wrapper maps **`-ffile-prefix-map=$out=/usr`**
   (WP4/E1): headers reached through the alias are otherwise recorded in DWARF
   as `$out/include/...` — dangling self-references (glibc: 8 files, all
   DWARF; one masked as "backed", see below).

Evidence: glibc built from the **unmodified** spec (`--with-headers=%{_prefix}/include`
resolved through the alias, no `specSubstitutions`) and 6 small SRPMs build
with the view; against the no-view builds the outputs have identical file
lists and identical code/data — every difference is in non-loaded DWARF
(glibc: 8 of 14020 files) or in build-ids that hash the store path.  A
positive control shows the view makes `%{_includedir}`-reached declared
inputs work and the reference scan catches what leaks.  `prefixView = false`
+ `specSubstitutions` stays as the per-package fallback (never needed here).

## Setup

Code: `lib/rocky/e2/` (experiment only), the shim itself:
`lib/rocky/tool-shim.sh`, `lib/rocky/mkview.py`, `lib/rocky/parts/toolShim.nix`
(test: `checks.nn-shim`).

* `reloc.nix`: one SRPM built by rpmbuild **outside** the FHS chroot, relocated
  to `%_prefix = $out`, nixpkgs cc-wrapper over the stage0 toolchain, tools from
  PATH, stage0 rpm 4.19 + Rocky macro packages as `/usr/lib/rpm` — the
  [NF-S3] recipe (`spikes-nixpkgs-faithful/glibc-reloc.nix`), generalised, run
  through `nn.toolShim` in two variants that differ **only** in the shim:
  * `noview`: `/usr` = PATH tools (`bin`, `sbin -> bin`) + `/usr/lib/rpm`, no
    alias — exactly the [NF-S3] shim;
  * `view`: additionally the declared inputs' `include lib lib64 libexec share`
    under `/usr` and the same view read-only at `$out` (`ROCKY_PREFIX_VIEW=1`).
  Declared inputs = the SRPM's library inputs (all of `dev`/`out`/`lib` of the
  nixpkgs stand-ins) + its BuildRequires tool packages; generic stdenv tools are
  PATH-only.  Library inputs also go to the cc-wrapper (`buildInputs`) in both
  variants.
* Same store name in both variants (same `$out` length), one fixed gcc random
  seed (`NIX_OUTPATH_USED_AS_RANDOM_SEED`), so outputs are byte-comparable
  modulo the own store hash.  The payload is the whole rpm BUILDROOT under
  `$out` (no partition).
* `compare.py`: relative file lists (`.build-id` links keyed by target),
  contents classified identical / modulo own hash / modulo pieced hash runs /
  modulo build-id (ELF32/64, section by section; MiniDebugInfo decompressed) /
  modulo ar dates / DWARF-ONLY (only non-loaded `.debug_*` sections differ) /
  DIFFERS, symlink targets; and a reference scan of every
  file (raw, gzip members, compressed ELF sections, MiniDebugInfo): each
  `$out/<rel>` is *backed* (exists in the output), **DANGLING-IN-VIEW** (no file
  of the build, but present in the build's view — a compiled-in reference into
  the view), or *dangling*; plus references to other store paths.

```
nix build -L --cores 6 --max-jobs 2 .#checks.x86_64-linux.nn-shim
nix build -L --cores 6 --max-jobs 2 .#nn.toolShim.e2.{which,xz,gzip,sed,m4,expat,probe}.compare
nix build -L --cores 6 --max-jobs 2 .#nn.toolShim.e2.glibc.compare
python3 -I lib/rocky/e2/compare.py OUT <nf-s3 glibc> <noview> <view>     # determinism control
```

## Results: six small SRPMs

All 12 builds succeeded.  `view` vs `noview` (reports:
`e2-compare-<srpm>/report.txt`):

| SRPM | declared view inputs | entries (both) | file contents | links | unbacked `$out` refs new in view | other store paths new |
|---|---|---|---|---|---|---|
| which | 4 (readline, ncurses dev+out) | 43 | 17 identical, 2 modulo build-id | same | 0 | none |
| xz | 7 (autoconf automake libtool gettext gnupg gpgv2) | 525 | 290 identical, 10 modulo build-id, 1 modulo hash | same | 0 | none |
| gzip | 4 (autoconf automake less, texinfo 7.1 FHS tree) | 120 | 94 identical, 2 modulo build-id | same | 0 | none |
| sed | 4 (acl, libselinux (+pcre2), autoconf automake) | 217 | 109 identical, 2 modulo build-id | same | 0 | none |
| m4 | 3 (autoconf automake gettext) | 302 | 220 identical, 2 modulo build-id | same | 0 | none |
| expat | 7 (autoconf automake libtool xmlto gnupg gpgv2) | 80 | 39 identical, 4 modulo build-id, 1 modulo hash | same | 0 | none |

"modulo build-id" = the binaries and `.debug` files: only the build-id note,
`.gnu_debuglink` CRC and MiniDebugInfo differ, which hash the store path and so
differ between *any* two builds with different `$out`.  No file DIFFERS.  The
unbacked references in both variants are the same (FHS-depth `.build-id`
links: `lib/debug/.build-id/xx/*.debug -> ../../../../../usr/lib/debug/...`
is one level short under a 3-component prefix — a partitioner job, [NF-S5]).

**Positive control** (`lib/rocky/e2/probe/e2probe.spec`, a declared input that
is NOT a cc-wrapper input, reached only via `%{_includedir}/e2probe-dep`,
`%{_libdir}/pkgconfig`, `/usr/include/...`):

```
noview                                   view
missing include/e2probe-dep/...h         found   include/e2probe-dep/...h
missing lib64/pkgconfig/e2probe-dep.pc   found   lib64/pkgconfig/e2probe-dep.pc
missing /usr/include/e2probe-dep/...h    found   /usr/include/e2probe-dep/...h
found   /usr/bin/true /bin/sh /usr/bin/perl (both)
compiled-with-dep no                     compiled-with-dep yes
```

and the detector fires: `+ DANGLING-IN-VIEW $P/include/e2probe-dep <-
lib/debug/.../e2probe-...debug` (`.debug_line_str` names the header's
directory under `$out`, where no file of the build lives).  So the view does
what it is for, and anything it lets leak into an output is caught.

## Results: glibc

Both variants built (concurrently, `--cores 6`, ~24 min wall on the shared
machine).  `view`: 13 declared inputs (Rocky kernel-headers FHS tree, hoisted
`stage0.glibcBuildDeps`, texinfo 7.1, bison gettext perl python3 gawk procps
util-linux(dev,out,lib) gdb); collision report: only PATH shadowing (17
lines), no file collisions between inputs.  The spec is **unmodified**:

```
noview: --with-headers=/nix/store/<h>-rpm-kernel-headers/usr/include   (substitution, as [NF-S3])
view:   --with-headers=/nix/store/<h>-glibc-2.39-142.el10_2/include     (the spec's %{_prefix}/include, via the alias)
        checking for symlinks in /nix/store/<h>-glibc-2.39-142.el10_2/include... ok
```

`e2-compare-glibc/report.txt` (noview = A, view = B):

| | |
|---|---|
| entries | 17042 vs 17042, none only in one |
| identical | 12582 |
| modulo build-id (ELF, incl. `.gnu_debugaltlink` -> the dwz file's build-id) | 1414 |
| modulo own hash | 16 |
| **DWARF-ONLY** (every differing section non-loaded `.debug_*`) | **8** |
| DIFFERS (any loaded section / non-ELF content) | **0** |
| unbacked `$out` refs new in view | 3: `DANGLING-IN-VIEW $P/include/{linux,asm-generic,selinux}` |
| other store paths | `rpm-kernel-headers` no longer referenced in view |

The 8 DWARF-ONLY files: `lib64/ld-linux-x86-64.so.2` (+ its sysroot copy;
ld.so keeps DWARF), `lib/debug/.dwz/glibc-…`, and the `.debug` files of
`libc.so.6`, `libc_malloc_debug.so.0` (+ sysroot copy), `ldconfig`,
`makedb`.  The differing bytes are include-directory names in
`.debug_line`/`.debug_line_str` (and the offsets into them in `.debug_info`):

```
noview: /nix/store/<h>-rpm-kernel-headers/usr/include/{linux,asm-generic}
        /nix/store/<h>-glibc-build-deps-hoisted/include/{sys,selinux}
view:   /nix/store/<h>-glibc-2.39-142.el10_2/include/{linux,asm-generic,sys,selinux}
```

i.e. glibc compiles with `-isystem $sysheaders`, which now is the alias, and
evidently searches it before the cc-wrapper's `-isystem` of the build deps,
so sdt.h and the selinux headers are found there too (the same files: the
view contains glibcBuildDeps).  In the no-view build these names are *input* store paths
(a closure leak E1's prefix map removes); in the view build they are
*self* references that no file backs (`include/sys` is reported "backed"
because glibc ships an `include/sys/` directory: DWARF's directory table
names the dir, the file entry `sdt.h` separately — a dangling reference the
scan cannot see at directory granularity).  Hence condition 2 of the verdict:
`-ffile-prefix-map=$out=/usr` during rpmbuild turns all of them into
`/usr/include/...` (what Rocky's own DWARF says), safe because nothing but
the view lives under `$out` while rpmbuild runs.

**Determinism control** (by hand, the [NF-S3] build is a store path literal):
`compare.py <NF-S3 nncpaslng…> <noview> <view>`: NF-S3 vs our `noview` —
17042 entries both, 12547 identical, 724 modulo build-id, 16 modulo hash,
733 DWARF-ONLY, 0 DIFFERS, no new unbacked refs.  The 733 are the gcc random
seed: [NF-S3] ran nixpkgs' reproducible-builds hook seeded with its own
`$out` (`-frandom-seed=nncpaslng9` in `DW_AT_producer`), E2 fixes the seed
for both variants; that string changes `.debug_str` and every
`.debug_info` offset into it.  So the [NF-S3] shim and `nn.toolShim` without
inputs produce the same glibc, and the view adds exactly the 8 DWARF-ONLY
files above.

## Findings along the way (fed to other work packages)

1. **The view must be real directories, not a symlink farm.**  First glibc
   `view` attempt failed in configure: `sysdeps/unix/sysv/linux/configure`
   checks `test -L ${prefix}/include/{net,scsi}` ("'make install' will
   destroy the target of the link(s)") and the symlink view had
   `$out/include/scsi -> <kernel-headers>/usr/include/scsi`.  The shim now
   mounts `include lib lib64 libexec share` as read-only **overlayfs** of the
   inputs' directories (bwrap `--overlay-src`/`--ro-overlay`, the lib/chroot.sh
   mechanism; first input = topmost; one input = a bind), on a tmpfs at `/usr`
   and at `$out` that is remounted read-only.  Only `bin` stays a symlink farm
   (PATH tools).  `checks.nn-shim` asserts real dirs/files and read-only-ness.
2. **DWARF names view files by their `$out` path.**  A header reached through
   the alias is recorded as `$out/include/...` (positive control; glibc:
   kernel headers, see above).  E1's `-ffile-prefix-map=<input>=/usr` does not
   see those; with `prefixView` the cc-wrapper hook must also map
   `-ffile-prefix-map=$out=/usr` while rpmbuild runs — safe, because during
   rpmbuild nothing but the view lives under `$out` (the shim enforces `$out`
   empty before and after).
3. `config.site` must end with status 0: autoconf >= 2.70 aborts with "failed
   to load site script" when the last `test ... && x=...` did not match
   (which's configure passes `--sharedstatedir=/var/lib`).  Design §1.3's
   snippet has this bug (trailing `:` fixes it).
4. **Macro files in `/usr/lib/rpm/macros.d/` lose against the platform
   file.**  rpm 4.19's macro path is `macros : macros.d/macros.* :
   platform/%{_target}/macros : fileattrs : redhat/macros : /etc/rpm/macros.*
   : ...`, and `platform/x86_64-linux/macros` defines `%_prefix
   %_exec_prefix %_bindir %_sbindir %_libexecdir %_datadir %_sysconfdir
   %_sharedstatedir %_localstatedir %_lib %_libdir %_includedir
   %_oldincludedir %_infodir %_mandir %_initddir %_rundir %_defaultdocdir
   %__spec_install_pre %__arch_install_post %__brp_* %__os_install_post
   %__spec_install_post`.  So design §1.2's `macros.d/macros.zz-nix-reloc`
   would be silently overridden for exactly the relocation macros.
   Measured in the shim (stage0 rpm 4.19.1.1, Rocky macro packages), with
   `macros.d/macros.zz-e2` = `%_prefix /e2/macros.d`, `%_sysconfdir /e2/etc`,
   `%e2_marker set` and `%_libdir /e2/redhat/lib64` appended to
   `redhat/macros`: `rpm` and `rpmbuild`, with and without `--target x86_64`,
   all print `_prefix=/usr _sysconfdir=/etc _libdir=/e2/redhat/lib64
   e2_marker=set` (the file IS read; the platform file wins).  Also
   `rpmbuild --load FILE` is **dropped** when `--target` re-reads the
   configuration (seen: sed's `rm -rf $RPM_BUILD_ROOT` left unpackaged
   `/usr/src/debug/*` because the realias in `__spec_install_post` never
   ran).  What works: `--define` (single line, as [NF-S3]), appending to the
   build's copy of `redhat/macros` (E2), or a file in `/etc/rpm/` (would need
   a bind in the shim).
5. `check-rpaths` (`%__arch_install_post`) rates every absolute RUNPATH outside
   `/lib*`, `/usr/lib*` as "invalid" (0x0002) and fails the build: store
   RUNPATHs need `QA_RPATHS=0x0002` (design §5.5 says "not needed": wrong).
6. Rocky tool names the specs/macros call: `/sbin/ldconfig` (redhat
   `brp-ldconfig`; glibc's spec disables it), `gpgv2` (`%gpgverify`).  With
   the shim they are just PATH entries (`/sbin -> usr/bin`).
7. S1 hazard: nixpkgs libraries linked into binaries that use the stage0 libc
   2.39 pull nixpkgs glibc 2.42's `libdl.so.2`/`libpthread.so.0` through their
   RUNPATH, whose stubs need `GLIBC_ABI_DT_X86_64_PLT` → the program (sed/sed,
   run by help2man) does not start.  E2 used RUNPATH-patched copies
   (`forStage0Libc`) for acl/libselinux.  `stage0.glibcBuildDeps`' version
   check would not catch it (it skips nixpkgs glibc itself and compares
   `GLIBC_2.x` versions only); harmless there because nothing linked against
   those libraries runs during the glibc build.
8. nixpkgs' reproducible-builds hook seeds gcc with `$out`'s hash: the seed
   lands in `DW_AT_producer` (`-grecord-gcc-switches`) and changes the order of
   `.debug_str`, so two builds with different `$out` differ in DWARF beyond the
   path — another reason for design §5.1's "hook off" (E2 fixed the seed).
