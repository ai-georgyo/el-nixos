# E3: do RUNPATH recompute + gated stubs remove the overrides of `foo`/`foo-libs`/`-common` SRPMs?

Design §9 E3, work package WP0c; the rules are the ones of
`tools/rocky-partition` (WP5, design §2.5–2.9). Date: 2026-10-18.

## Setup

Relocated build trees (`%_prefix = $out`, BUILDROOT and header-only RPMs
kept) from `tools/rocky-partition/tests/trees.nix` → `reloc-tree.nix`, the
[NF-S3] spike recipe as a function: rpmbuild outside the chroot in a bwrap
tool shim (`/usr/bin` = PATH tools, `/usr/lib/rpm` = stage0 rpm + Rocky
macro packages), `BUILDROOT/usr` folded onto the prefix. For E3 the compiler
is **nixpkgs' cc-wrapper** (gcc 15, gcc 14 for ncurses/libxcrypt) and the
BuildRequires come from nixpkgs (`buildInputs`): the subject is the
partition, not the toolchain. CONFIG_SITE = the design's §1.3 file
(`tests/config-e3.site`).

```sh
# trees (legacyPackages.x86_64-linux.nn.partitionTool.trees.e3.<srpm>)
nix build -L --cores 6 --max-jobs 2 --impure -f trees.nix e3.xz e3.expat e3.libxcrypt e3.ncurses e3.krb5
# partition: replay each tree into same-length fake outputs (a /tmp/pstor store dir),
# plan = subpackage map by the §2.12 naming rule + per-run overrides
python3 -I dev.py <tree>/buildtree <srpm> <overrides.json|-> <run>
```

(`dev.py` is a scratch driver around `rocky-partition --replay`; it is the
same code path as `checks.nn-partition-replay`, minus Nix's own output
check.) Each RUNPATH of these trees holds nixpkgs' self-rpath `$out/lib`,
the nixpkgs glibc and gcc-lib dirs (libtool adds `$out/lib64` where it
relinks); the partitioner keeps input store paths and recomputes the rest.

## Rule changes made during E3 (fed into WP5, all implemented)

Measured error counts with the rules **as first implemented from the design
text** (column "v0") led to these changes:

| # | change | why (evidence) |
|---|---|---|
| R1 | store-by-pieces windows must contain ≥ 6 bytes of the prefix's hash (were: any 8-byte window of the prefix) | xz: 3 `pieced-unacked` in `.note.package` (windows of the *name* `xz-5.6.2-4.el10_2.1`), whose hidden-references then closed a false cycle lib↔out; glibc: 79 false pieces in benchtests; selftest: a window `/store/<1 hash char>` matched an unrelated store path |
| R2 | text in a non-prefix output Y that owns part of a `lib64`/`lib`/`include` union dir is rewritten to `$Y/...` (`union-self`) | every `-devel` `.pc`: `libdir=$out/lib64` is a union (the `-libs`/`-devel` split puts `libfoo.so` in dev) → was `prefix-relative` (xz, expat, libxcrypt, ncurses ×12); `$dev/lib64` is where `-lfoo` finds `libfoo.so`. Restricted to lib/include dirs: in ncurses6-config the same rule turned `datadir=$out/share` into `$dev/share` (wrong) |
| R3 | a pkg-config variable whose value is the bare prefix is acked when neither it nor a variable derived from it (`exec_prefix=${prefix}`) is used by another line | `.pc` files of all 4 libraries: `prefix=`/`exec_prefix=` are written expanded and unused (`prefix-relative` ×2 per file) |
| R4 | a reference to a *standard top-level* directory that several outputs fill (`$out/bin`, `$out/lib64`, `$out/share`) is the design's case 5 (prefix-relative), not case 3 | the design table already says "bare `$out` or `$out/` prefix of a union"; glibc's 32-bit ld.so names `$out/lib` (system dir) |
| R5 | ld.so dynamic string tokens (`$LIB`, `${PLATFORM}`, also shell-escaped `\$LIB`) are part of a path; `$LIB` expansions `lib64`/`lib` are classified | glibc `memusage`/`xtrace`: `memusageso='$out/\$LIB/libmemusage.so'` was "bare prefix" (`\` ended the path); libmemusage.so is in **utils**, so the reference must be rewritten (now `$utils/\$LIB/...`, a real functional fix) |
| R6 | debug build-id links `../../../.build-id/xx/yy` to a dropped `usr/lib/.build-id` link are followed to the binary | glibc: 708 `symlink-dangling` in debug (design §2.2 drops those links) |
| R7 | debug and unmanaged outputs are not part of L* (they may reference siblings, they are not rebound) | glibc: debug reached common/utils/nss_db through R6's links |
| R8 | references from documentation trees (`share/doc`, `share/man`, `share/info`, `share/gtk-doc`, `share/help`) are recorded (Nix still sees the edge) but never errors | krb5-workstation: 7 `prefix-relative` in the HTML admin guide (`$out/sbin`, `$out/lib64` as prose) |
| R9 | `#!/bin/sh` and `#!/usr/bin/env` are runtime FHS (design §1.4), not `fhs-shebang` warnings | krb5-tests: 8 warnings |
| R10 | `prefixRelativeOk` (new plan key, design §8.1 lacks an ack for case 5) also acks union and dangling references of the matching files | krb5-tests (an unshipped copy of the build tree: Makefiles, config.status): 1097 prefix-relative, 241 union, 129 dangling references, all meaningless at run time |
| R11 | header paths below *another* output's path are mapped too (`layout = { _sbindir = "server"; }` builds) | needed for the `layout` remedy of §2.7 at all (selftest `layout_and_docs`; not exercised on a real tree) |

The design's §2.6 (RUNPATH) and §2.7 (gated stubs) needed no change.

|---|---|---|---|---|---|---|---|

### xz (xz / xz-libs, the `foo`/`foo-libs` case)

RUNPATH recompute does the whole job: `bin/xz`, `bin/xzdec`, lzma_compat's
`lzmadec`/`lzmainfo` had `$out/lib:<glibc>/lib:<gcc-lib>/lib` (nixpkgs
self-rpath + wrapper); now `$lib/lib64:<glibc>/lib`; `liblzma.so.5.6.2`
itself `<glibc>/lib` (own dir and unused gcc-lib dropped). Graph: out→lib,
dev→{lib,out}, lzma_compat→{lib,out}; no cycle, no stub, no override.

### expat, libxcrypt (no `-libs`: the library is in `out`)

Only the `.pc` handling (R2, R3) mattered; dev→out. libxcrypt-compat
(`libcrypt.so.1`) gets its own output with RUNPATH `<glibc>/lib`.

### ncurses (`ncurses-base` terminfo, `ncurses-term`)

With the eponymous prefix (§3.1 rule) 325 errors:
* 304 `binary-ref`: compiled terminfo entries of base (4) and term (300)
  carry `if=$out/share/tabset/vt100` (init file). `share/tabset` belongs to
  ncurses-base; base → `$out/share/tabset` is Y == X ≠ out (a stub out→base
  would close a cycle); term → base would need the same stub.
* 1 cycle lib↔out: `libtinfo.so.6` compiles in `$out/share/terminfo`
  (default TERMINFO) while every out binary needs libtinfo (RUNPATH).
* 12 `union-unacked` (`share/terminfo` = base + term, `share/man`) and 8
  `prefix-relative` (`ncurses6-config`/`ncursesw6-config` report
  `prefix`, `exec_prefix`, `bindir`, `datadir`, `mandir`).

Stubs cannot help here: the data that the libraries compile in is itself a
non-prefix subpackage. What works without any merge is **choosing
`ncurses-base` as the prefix subpackage** (it owns `share/terminfo` and
`share/tabset`, references nothing): base = out; lib → out, term → out,
ncurses (binaries) → lib; terminfo union via `TERMINFO_DIRS` (setup hooks
generated for out and term). Alternatives measured: TERMINFO ack only → 315
errors; prefix base + TERMINFO without the config-script ack → 10 errors;
merge `[ncurses ncurses-libs ncurses-base]` + TERMINFO → 10 errors
(the config scripts) and 2 outputs fewer. The `*-config` scripts are genuinely
prefix-relative (they print install dirs) → ack.
Proposal for WP1's prefix rule (§3.1): before "eponymous", prefer a
subpackage that owns a directory compiled into the `-libs` subpackage and
references no sibling (here: base). Not implemented in the lock generator
(not mine); for now `prefixSubpackage = "ncurses-base"` in
`packages/ncurses`.

### krb5 (no eponymous subpackage; prefix = krb5-libs)

The prefix rule of §3.1 (no eponymous subpackage → `krb5-libs`) works:
the libraries are `out`, every program output reaches it, RUNPATH entries
for `$out/lib64` stay and nixpkgs' `$out/lib` self-rpath and unused
dirs are dropped (37 files). 1476 errors without overrides:

* 1467 come from **krb5-tests** (unshipped, design §0.4 #4: still an output):
  a copy of the configured build tree (Makefiles, config.status, config.log,
  osconf.h) full of `$out`, `$out/bin`, `$out/lib64/gss` → one
  `prefixRelativeOk = [ "tests" ]` (R10).
* `krb5-config` (dev) prints `prefix`/`exec_prefix`: ack (same class as
  ncurses6-config).
* `libgssapi_krb5` names `$out/lib64/gss/` (GSS mechanism plugin dir, filled
  by other packages): `danglingOk`.
* `libkrb5`/`libkdb5` load plugins from `$out/lib64/krb5/plugins/{preauth,kdb,authdata,...}`,
  a union of out, pkinit, server, server_ldap, xrealmauthz: `unionDirs` ack —
  a real functional limit: a plugin in another output is found only through
  composition (krb5.conf `[plugins] module = <path>` or a profile/buildEnv),
  design §4.1 (3).
* 3 `binary-ref` in krb5-server: `kadmind`/`kpropd` run `$out/sbin/kdb5_util`
  and `$out/sbin/kprop`, which are server's own (Y == X ≠ out: a stub would
  close a cycle). Remedies: `layout._sbindir = "server"` (§2.7's validity
  rule forbids it: krb5-server-ldap also has `sbin/kdb5_ldap_util`; not
  tried, it needs the second output path at build time), or merging
  krb5-server into out — which then cycles with libkadm5 (libkadm5 links
  libkdb5, out's kdb plugins link libkadm5) → `mergeOutputs = [ [ "krb5-libs"
  "libkadm5" "krb5-server" ] ]` → 0 errors, 7 outputs + debug.

### What RUNPATH recompute and gated stubs did, in numbers

* RUNPATH recompute replaced the `foo`/`foo-libs` override in every case
  (xz, ncurses, krb5); 0 `unresolved-needed`, 0 `ambiguous-needed`.
* Requires-gated forwarding stubs: **0 created** in all five SRPMs and in
  glibc. Every compiled-in reference into a non-prefix output was either
  self-referencing data (Y == X: ncurses-base, would cycle) or into data of
  the prefix-to-be (ncurses after the prefix change). The rule stays (it is
  covered by `checks.nn-partition-selftest`, case `split`), but E3 found no
  SRPM that needs it.
* The `-common` data class (ncurses-base) is not solved by stubs; it is
  solved by the prefix choice.

## Build hazards met while making the trees (not partition rules)

They matter for WP2/WP6 (macro file, check scripts) and are reported there:

1. **config.site must end in `true`**: autoconf ≥ 2.70 aborts with "failed
   to load site script" when the script's exit status is non-zero; the
   design's §1.3 file ends with `test ... && ...` (false for a normal
   `runstatedir`). glibc's old configure does not check, so [NF-S3] never saw it.
2. **brp `check-rpaths`** calls every absolute RUNPATH outside
   `/usr/lib*`/`/lib*` "invalid" (0x0002) and fails the build: every store
   RUNPATH, also the self-rpath of the Rocky toolchain. Needs
   `QA_RPATHS=0x0002` (or `%__brp_check_rpaths %{nil}`); design §5.5 says
   "QA_RPATHS not needed" — wrong.
3. **brp-ldconfig** (`/sbin/ldconfig -N -r $BUILDROOT`) with nixpkgs' ldconfig
   fails (cache dir); off for E3.
4. **libxcrypt** `%install` deletes every non-directory of the buildroot,
   including the `BUILDROOT/usr` fold link; find-debuginfo then writes a real
   `BUILDROOT/usr/src/debug` and check-files reports it unpackaged. libxcrypt
   also redefines `__spec_install_post`, so a fold-usr hook there would not
   run either. The partitioner reads both forms (it locates header paths
   through `BUILDROOT/usr` whatever it is); check-files must too.
5. **krb5** `%define libsdocdir %(echo %{_pkgdocdir} | sed -e s,krb5,krb5-libs,g)`
   rewrites the store name of the prefix as well (`…-krb5-libs-1.21.3…`):
   a relocation hazard for every spec that edits macro-expanded paths with
   the package name. specSed in the test tree.
6. **krb5** reaches its build environment through target macros
   (`source %{_libdir}/tclConfig.sh`, `-I%{_includedir}/et`): E2's
   self-prefix alias case; specSed in the test tree.
7. krb5: `git am` under `%autosetup -S git` failed twice with "invalid
   object" (auto gc racing `git am`); `gc.auto=0` via `GIT_CONFIG_*`.

Toolchain-only workarounds (nixpkgs vs Rocky): gpg2/gpgv2 names, gcc 14 for
ncurses 6.4's C++ binding and libxcrypt's `-Werror`, `compile_et` from
`e2fsprogs.scripts`, a `<openssl/fips.h>` shim, autoconf instead of
autoreconf for krb5.

## Verdict

* §2.6 RUNPATH recompute: **keep as designed**; it removes the `foo`/`foo-libs`
  overrides (xz, ncurses, krb5: 0 errors from libraries in a `-libs` output).
* §2.7 gated stubs: keep (cheap, tested) but they solved nothing in E3.
* Text rules needed tuning for `-devel` build descriptions (R2, R3) and
  ld.so tokens (R5); detection rules R1, R4, R6, R7 — all implemented in
  `tools/rocky-partition`.
* Remaining override classes: (a) prefix choice for packages whose libraries
  compile in a data subpackage (ncurses → base); (b) acks for files that
  print install dirs (`*-config`) and test/sysroot/build-tree copies (glibc
  benchtests and sysroot, krb5-tests); (c) search paths / union acks for
  data and plugin dirs (terminfo, locales, gconv, krb5 plugins); (d) a merge
  where programs of a non-prefix output run each other by compiled-in prefix
  path (krb5-server: kadmind → kdb5_util, kprop).
* Count: xz, expat, libxcrypt need **no** override; ncurses 3 entries (one
  of them the prefix choice), krb5 4 entries (one merge). With the design's
  rules as first written, all five needed overrides (xz and expat for their
  `.pc` files alone).

Not done: no behaviour test of the split trees (the outputs were not run);
the krb5 tree used nixpkgs libraries, so its RUNPATHs name nixpkgs paths
(kept as inputs).
