# E6: nixpkgs wrapCCWith/wrapBintoolsWith over a non-nixpkgs stdenvNoCC

Question (design §9 E6, WP16): when the nixpkgs cc-wrapper / bintools-wrapper
*sources* are instantiated with a stage's own `stdenvNoCC`, which nixpkgs
derivations still leak into the build, and does the eval-time build-purity
assertion (`lib/rocky/purity.nix`, design §7.3) flag exactly those?

Date 2026-10-18; nixpkgs 26f4107e (nixos-26.05; gcc 15.3.0, binutils 2.46,
glibc 2.42); Determinate Nix 3.23.1 (Nix 2.36.0), `lazy-trees = false`.

## Setup (`lib/rocky/checks/purity.nix`, exposed as `checks.x86_64-linux.nn-purity.e6`)

* **Stand-in tools** (`e6.tools`): 18 fresh `builtins.derivation`s
  (`e6-coreutils`, `e6-bash`, `e6-gcc-15.3.0` (out + lib), `e6-glibc-2.42`
  (out, dev, bin), `e6-binutils-2.46`, `e6-expand-response-params`, …) whose
  outputs are symlinks to the nixpkgs outputs. The E6 stage lists exactly these
  in `allowedBuildDrvs` (`purity.drvSet`), as S3 would list S2/S3 packages.
* **stdenvNoCC** = `import "${nixpkgsSrc}/pkgs/stdenv/generic" { cc = null;
  initialPath = <the 14 common-path stand-ins>; shell = e6-bash; … }`.
* **naive**: `bootPkgs.wrapBintoolsWith { bintools = e6-binutils; libc =
  e6-glibc; stdenvNoCC; }`, `bootPkgs.wrapCCWith { cc = e6-gcc; bintools;
  libc; stdenvNoCC; isGNU = true; }`, stdenv = generic stdenv with that cc.
* **full**: as naive, plus `runtimeShell = "${e6-bash}/bin/bash"`, `coreutils`,
  `gnugrep`, `expand-response-params` = the stand-ins.
* A package of each stage: `e6-hello` (compiles and runs a C program with
  `gcc` in `buildPhase`).

### 3. The composition really works

```
nix build -L --cores 6 --max-jobs 2 --no-link .#checks.x86_64-linux.nn-purity.e6.hello.{full,naive}
e6-hello> hello from the E6 stdenv        (both; exit 0)
```

(First attempt failed with `gcc: command not found`: a stand-in with outputs
sorted `lib, out` makes `lib` the default output, so the wrapper's `$cc` was
gcc's lib. Fixed by putting `out` first; worth remembering for mkRpmPackage's
output order, where `out` must also be first.)

### 4. Sources

`utils.bash` and `darwin-sdk-setup.bash` come from
`pkgs/build-support/wrapper-common` (substituted by both wrappers' postFixup),
which the design's list (§7.3) does not name. With that root removed from
`lib/rocky/allowed-sources.nix` the full stage fails:

```
  - source /nix/store/6b9v7v02npab086yaba2j4yfqrph5mgp-utils.bash (not a copy of an allowed source file)
      via e6-hello.stdenv > e6-stdenv.defaultNativeBuildInputs[14] > e6-gcc-wrapper-15.3.0.postFixup (+2 more chain(s))
  - source /nix/store/6xizqkp4bnhydwc7ihyqi93171gbj5n4-darwin-sdk-setup.bash (not a copy of an allowed source file)
```

so it is in the list, as is `pkgs/by-name/ex/expand-response-params` (the C
source design §5.1 compiles with the stage; not exercised here, E6 re-exports
the binary).

How sources show up (Nix 2.36): a path value stays a path in drvAttrs
(checked by prefix); `"${./x.sh}"` puts a store *copy* `<h>-x.sh` into the
context (checked by hashing the same-named files under the allowed roots,
lazily, by name); `"${nixpkgsSrc}/…"` / `"${repo}/…"` copy the *whole tree*
(`<h>-<h0>-source`): for nixpkgs that is a violation (the whole tree is not an
allowed source), for the repo it matches the root's copy.

### 5. Eval cost

`e6.scale mode n`: n trivial packages of the full stage (each with a lock FOD
`src`, two stand-in inputs), `deepSeq` of all drvPaths; `NIX_SHOW_STATS`
cpuTime, warm store, two runs each:
`NIX_SHOW_STATS=1 nix eval --raw .#checks.x86_64-linux.nn-purity.e6.scale --apply 'f: f "<mode>" <n>'`

| mode | n = 1 | n = 2200 | cost of the check for 2200 |
|---|---|---|---|
| plain (no check) | 0.56 s | 1.81 / 1.86 s | — |
| `check` with a per-package checker | 0.57 s | 5.71 / 5.56 s | +3.8 s (≈1.7 ms/pkg) |
| `check` with `stage.purityChecker` (shared memo) | 0.57 s | 2.22 / 2.16 s | +0.35 s (≈0.16 ms/pkg) |

Thunks for 2200: plain 0.94 M, shared 1.44 M, per-package 7.1 M. So the stage
must carry `purityChecker = purity.forStage stage` (one memo of the stdenv,
stdenvNoCC, cc and bintools drvAttrs per stage); then the check is ~20 % of
the evaluation of a trivial package and less for real ones.

A lock FOD reached *only* through a string context (`"${src}"` instead of
`src = …`) forces the drvPaths of all 2217 lock FODs once: +0.75 s cpu
(0.60 → 1.38 s; `purity.violations` of a package with `src = fetchSrpm "which"`
vs `unpackPhase = "echo ${fetchSrpm "which"}"`), once per evaluation
(module-level memo).

`nix-eval-jobs` (`tools/build-jobs.sh --attr hydraJobs.checks --dry-run`,
IFD disabled): 31 checks evaluated, 0 errors, `nn-purity` included.

## checks.nn-purity

33 pure-eval tests, results baked into the derivation env; the build prints
them and fails if one failed (`nix build -L .#checks.x86_64-linux.nn-purity`:
33 × ok). The check derivation depends only on bash/stdenv, not on any test
derivation. Tests: E6 (full pure, naive = exactly the 4 drvPaths, naive
throws, message names the derivation and the chain, 4 memo seeds); nixpkgs
derivation as input / in a string / as `.drvPath` string; nixpkgs stdenv;
stage0 derivation; official-RPM FOD (not allowed); foreign FOD; lock FOD as
value and in a string; `allowLockFods = false`; `disallowedRequisites`
ignored; structured attrs (`.env.FOO`); plain attrs; whole nixpkgs tree;
nixpkgs path outside the roots; copy of a nixpkgs file outside the roots with
a name that exists inside them (`default.nix`); allowed hook as path and copy;
repo files (string, copy, path); `builtins.toFile` (unidentified source);
`extraAllowedSources`; `assertBuildPure` identity/throw; `check` no-op without
`buildPure`, guards `drvPath` and output `drvPath`s, leaves `outPath` lazy,
identity when pure; shared checker gives the same results.

`nix build --dry-run .#checks.x86_64-linux.nn-purity.e6.checked.naive` fails
evaluation with the report above (the guard on `drvPath`, as mkRpmPackage's
`purity.check stage` would).

## Verdict

* Instantiating nixpkgs' wrappers over a stage `stdenvNoCC` leaves exactly
  four nixpkgs derivations per wrapper: `runtimeShell` (bash), `coreutils`,
  `gnugrep`, `expand-response-params`. WP4 (`lib/rocky/cc/wrap.nix`) must pass
  all four explicitly from S2 on; then the wrappers are build-pure.
* The assertion detects them at eval time with the attribute chain, matches
  Nix's inputDrvs exactly, passes when they are overridden, needs no build and
  no IFD, and costs ≈0.16 ms per package with a shared per-stage checker.
* Allowed sources need `pkgs/build-support/wrapper-common` in addition to the
  design's list.

## Not done / limits

* The stand-ins are nixpkgs outputs re-exported, not Rocky builds; S2/S3 will
  supply real ones. The expand-response-params-from-C-source path is not built.
* Context-free store paths (`unsafeDiscardStringContext`) are invisible to
  the assertion by construction; the output-closure checks (§7.1, §7.2) cover
  them for outputs, nothing covers them for build inputs.
* `disallowedReferences`/`disallowedRequisites` are ignored by default: Nix
  realises their derivations as inputs (string context), so design §7.1's
  "disallowedRequisites = every S0/S1/S2 derivation" puts those in the S3
  sandbox. Harmless only as long as nothing names them; worth revisiting.
* Not measured with real mkRpmPackage derivations (WP6 does not exist yet).
