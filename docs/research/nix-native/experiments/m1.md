## Findings on the real glibc and what was done

The WP9 checks had only run on the replay glibc (the [NF-S3] spike tree:
no P2, no P3, no trusted dirs, built without the S1 wrapper). On WP7's
build (`xl44f3c0…`) `nn-glibc-closure` passed and the other four failed:

1. **New dtags changed every dynamic section (abi 705, content ~280
   unexpected).** The S1 ld wrapper puts `--enable-new-dtags` first on
   every link (so its store `-rpath` entries become DT_RUNPATH). Rocky's ld
   defaults to old dtags, so ld wrote `-z now` as `DT_FLAGS BIND_NOW`
   instead of `DT_BIND_NOW` in every glibc program and library, and the 14
   gconv modules linked with `-rpath '$ORIGIN'` got DT_RUNPATH instead of
   Rocky's DT_RPATH (RUNPATH yields to `LD_LIBRARY_PATH`, RPATH does not).
   glibc sets no store rpath at all (`NIX_DONT_SET_RPATH`), so the flag has
   no purpose there. Fix: glibc's override sets `NIX_LDFLAGS_BEFORE =
   --disable-new-dtags`, which the ld wrapper places after its own flags and
   before the link's arguments. A first try with `NIX_LDFLAGS_AFTER`
   (after the arguments) also overrode glibc's own
   `-Wl,--enable-new-dtags` for `librt.so.1` (rt/Makefile), which Rocky's
   librt has: measured as the one remaining abi/content difference, fixed by
   the `BEFORE` placement. Not an allowlist entry: the difference was ours.
2. **P2 added a PLT slot to libc.so.6.** nixpkgs' `nix-locale-archive.patch`
   calls the public `secure_getenv` inside libc (loadarchive.c), so
   libc.so.6 gained an `R_X86_64_JUMP_SLOT secure_getenv@@GLIBC_2.17`
   (content: `.plt`, `.plt.sec`, `.got`, `.rela.plt` of libc.so.6 grew by
   one entry). That is interposable: a program defining `secure_getenv`
   would be called by libc while it opens the locale archive (glibc's own
   `check-localplt` forbids it). Fix: the loadarchive.c hunk calls glibc's
   hidden `__libc_secure_getenv` (declared in include/stdlib.h, same
   function). One deliberate difference from nixpkgs' patch text, recorded in
   the patch header; the programs (locale.c, locarchive.c) keep the public
   call, as nixpkgs. libc.so.6 now has no PLT slot for it.
3. **Runtime normaliser bug (tool).** usrmerge canonicalisation turned the
   label `<libgcc>/lib64/` into `<libgcc>/usr/lib64/` (the `>` of the label
   was not a path character to the lookbehind), so `ldso.help` and
   `ldso.diagnostics` matched no rule. Fixed in `tools/nn-parity.py` with a
   unit test.
4. **P3 assertion bug (test).** `n "P3: /etc/ld.so.preload ignored"` grepped
   the section including its header `### p3.ld.so.preload`, so it always
   failed; its counterpart grepped the whole file and was satisfied by the
   header `### p3.ld-nix.so.preload`, i.e. vacuous. Both now read the section
   bodies only; a third assertion checks the program ran with an
   `/etc/ld.so.preload` present. Measured: the loader ignores
   `/etc/ld.so.preload` and reads `/etc/ld-nix.so.preload` (P3 works).
5. **Real, named differences** (allowlist rules, each pinned):
   * **P1** `path.sysconfdir` in `ld.so --list-diagnostics` is `$out/etc`
     (P1's dl-diagnostics.c prints `PREFIX "/etc"`; libc keeps `/etc`).
   * **P2** `locale`/`localedef` call `secure_getenv`: one more undefined
     dynamic symbol, a GLIBC_2.17 version need (files: glibc-common's
     transient header gains `Requires: libc.so.6(GLIBC_2.17)(64bit)`),
     one more PLT/GOT entry; libc.a's `loadarchive.o` references
     `__libc_secure_getenv`.
   * **locale-alias** (new effect): libc expands locale aliases from
     `LOCALE_ALIAS_PATH` = its localedir, `$out/share/locale/locale.alias`,
     compiled in with no environment override, but `locale.alias` is a file
     of glibc-common (`$common/share/locale`; a stub `out → common` would
     close the cycle `common → out`). Of the 884 archive names exactly one
     needs it: `no_NO.ISO-8859-1` (stored with a non-normalised codeset;
     official resolves it through the alias to `nb_NO.ISO-8859-1`). Same
     root cause as the untranslated libc catalogs (decision §0.4 #6).

## Late binding in mkRpmPackage (WP11 wired, design §11.1)

`stage.pkgs.<srpm>` = `nn.lateBind.wrap raw` when the package declares
`lateBind` **and** `stage.lateBindFor srpm` is true; otherwise the raw
derivation. New mkStage parameters: `lateBindFor ? (srpm: false)`,
`lateBindPkgs ? { }` (libs by SRPM name not in `pkgs`), `interpreterPkgs ?
{ }` (shebang basename → package). Names resolve through
`lateBind.fromOverrides`; the bind derivation is built with the stage's
`stdenvNoCC`, `patchelf`, `python3` (`lateBind.mk`) and passes through the
stage's purity check (`checkBound`). `systemLibDirs` of the plan (`@out@`
substituted) make the NEEDED resolution strict.

Per-output passthru (new `passthruFor` hook of `lateBind.wrap`): an output
outside L* keeps raw's `rockyRequisites` minus the raw L* outputs; a bound
output adds the bound L* outputs and the binding packages' closures. A
package-level bound would put the bind derivation, which depends on e.g.
gd, into gd's own allowed lists when gd links glibc.out: an evaluation
cycle. `rockyOutputs`/`rockyOutputsByName` follow the bound outputs.

S1 does not bind (no Rocky bash/perl/python3/gd/libpng/libselinux):
`rockyBoot.s1.glibc` is the raw build, unchanged by the wiring (its
lateBind is read by the partitioner for the L* check and NEEDED/shebang
classification; its S1 `allowUnresolvedNeeded`/`fhsAllowlist` name the
exceptions). `checks.nn-glibc-late-bind` runs the same mkRpmPackage over a
copy of the S1 stage with `lateBindFor = glibc` and test stand-ins
(bash/sh, perl, python3 wrappers; per-library trees for gd, libpng,
libselinux from the S1 glibcBuildDeps; the real S1 zlib-ng):
